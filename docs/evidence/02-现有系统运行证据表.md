## 4. 当前可以回答的三个问题

### 问题 1：现有项目哪些能力可以保留？

目前证据最强的 KEEP 候选：

- Task / Execution / InputVersion；
- Session ownership；
- Active / View 上下文分离；
- Artifact / GDSX ingress；
- 版本及历史结果；
- Tool 契约、ToolRun 和错误边界；
- 外部公司 API Adapter；
- 参数 Schema 与业务硬校验；
- 阶段结果引用与数据一致性校验。

原因：这些主要解决**确定性安全与事实一致性**，不是模型智能决策问题。

### 问题 2：哪些自定义代码可能被 AgentScope 原生能力替代？

当前只能列为 VERIFY，尚不能下替换结论：

- System Prompt 中大量业务方法；
- Operation 语义解析的部分职责；
- Clarification 的语言理解部分；
- Plan 中“当前准备怎么做”的智能规划部分；
- 外层两个大型 Tool 的粒度；
- 四阶段人机交互的外围交互控制；
- 部分上下文和 Trace 能力。

原因：当前项目显式禁止 Skill，未验证原生 Plan / HITL；没有 A/B 实验。

### 问题 3：哪些功能必须写代码？

目前有较强理由继续使用确定性代码保障：

- 用户 / Session / Task 权限；
- Task / Execution / InputVersion 归属；
- 写前并发与 stale version 检查；
- 参数类型 / 范围 / 允许修改清单；
- 外部 API 调用及真实结果校验；
- 历史结果不可被半成品覆盖；
- ToolRun / 幂等 / 超时未知状态；
- 经专业确认后的计算依赖；
- Artifact / 大文件安全。

这些能力即使 AgentScope 原生实验表现良好，也不应仅依赖 Prompt 或 LLM 遵守。
